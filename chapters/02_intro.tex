\chapter{RISC-V 启动、Trap 与系统调用}\label{chap:trap-syscall}

启动、Trap 和系统调用共同决定内核如何进入运行状态、如何响应硬件事件以及如何接受用户态请求。原 IA-32/C++ 版本 Unix V6++ 依赖传统 PC 的实模式、保护模式、GDT、IDT、8259A 和 x86 中断返回栈帧；RISC-V/Rust 重构版本改用 OpenSBI、Sv39 页表、\texttt{stvec}、\texttt{scause}、\texttt{sepc}、\texttt{sstatus}、PLIC 和 SBI timer 等机制\cite{riscv_privileged_20211203,qemu_riscv_doc}。本章重点分析这些平台相关路径如何被重写，并说明 Rust 类型化上下文对 Trap 分发和错误返回的组织作用。

\section{内核启动与地址空间基础}

当前系统通过 QEMU 的 \verb|-kernel| 参数加载 RISC-V 内核镜像，并使用 OpenSBI 作为固件层。OpenSBI 完成机器模式下的基础初始化后，将控制权转交给内核。内核入口由链接脚本 \verb|src/kernel-riscv64.ld| 指定，入口符号为 \verb|_start|，加载地址为 \verb|0x80200000|。该地址位于 QEMU virt 平台常用的 DRAM 区域内，并避开了 OpenSBI 占用的低地址空间。

链接脚本将内核划分为 \verb|.bootstrap|、\verb|.text|、\verb|.rodata|、\verb|.data| 和 \verb|.bss| 等段。其中 \verb|.bootstrap.entry| 保存最早执行的入口代码，\verb|.bootstrap.stack| 保存启动阶段使用的静态栈空间，\verb|__bss_start|、\verb|__bss_end| 和 \verb|__kernel_end| 等符号供 Rust 代码在运行时定位 BSS 段和内核结束位置。内核入口 \verb|_start| 使用 Rust 裸函数和内联汇编实现，先将栈指针 \verb|sp| 设置到预留的 bootstrap 栈顶，再跳转到 \verb|riscv64_rust_entry|。Rust 入口清零 BSS 段，初始化串口、页表、页分配器、0 号进程、Trap、缓冲区、PLIC、定时器、文件系统根目录和控制终端，随后创建初始进程并进入调度器。

RISC-V 64 位平台常用 Sv39 分页模式。Sv39 使用三级页表，虚拟地址被划分为多级索引和页内偏移，页表项中包含有效位、读写执行权限、用户位、全局位、访问位和脏位等标志\cite{riscv_unprivileged_20191213,riscv_privileged_20211203}。当前系统在 \verb|src/machine/page_table.rs| 中定义 \verb|PageDirectory|、\verb|PageDirectoryEntry|、\verb|PageTable| 和 \verb|PageTableEntry| 等结构，用 Rust 类型对页表项编码、权限标志和页表数组进行封装。系统建立低地址用户映射入口、物理内存恒等映射、内核高地址映射和 MMIO 映射，并通过 \verb|satp| 与 \verb|sfence.vma| 使新的地址翻译规则生效。

启动阶段的边界与原 IA-32 版本不同。原版本需要在汇编中完成 BIOS 入口、磁盘扇区读取、GDT 设置、保护模式切换和跳转到高地址内核等步骤；重构后，机器模式下的大部分平台初始化由 OpenSBI 承担，内核侧的早期汇编主要集中在设置栈和跳转到 Rust 入口。启动阶段的工作重点由 PC 启动细节转向链接布局、页表建立和 Rust 裸机运行环境。

\section{Trap 处理总体框架}

RISC-V 将同步异常、异步中断和系统调用统一纳入 Trap 机制。当前系统在初始化阶段调用 \verb|init_trap|，将 \verb|stvec| 设置为 \verb|_trap_entry|，并通过 \verb|sscratch| 绑定当前进程的 \verb|TrapContext| 地址。此后，无论是用户态执行 \verb|ecall|、时钟中断到来，还是用户程序触发非法指令或页面异常，处理器都会跳转到同一个 Trap 入口。

\verb|_trap_entry| 使用裸函数和内联汇编实现。进入 Trap 后，汇编代码通过 \verb|csrrw| 交换 \verb|sscratch| 和临时寄存器，由此取得当前进程的 \verb|TrapContext| 指针。入口代码随后保存通用寄存器、\verb|sepc|、\verb|scause|、\verb|sstatus|、\verb|stval| 等状态；Trap 来自用户态时，还会切换到该进程的内核栈。上下文保存完成后，入口代码调用 Rust 层的 \verb|trap_handler| 分发事件；处理结束后恢复寄存器和控制状态，并执行 \verb|sret| 返回原执行流。

\figref{fig:trap-flow} 展示了这一统一入口的基本路径。原版本需要为系统调用、时钟中断、键盘中断和不同异常分别设置 IDT 表项，并在多个入口函数中保存现场、切换内核、调用处理函数、恢复现场和 \verb|iret| 返回。RISC-V 版本把入口收束到 \verb|_trap_entry|，再由 Rust 层根据 \verb|scause| 判断事件类型。入口路径集中后，异常、中断和系统调用共享同一份上下文结构，后续分发也更容易沿 \verb|TrapContext| 追踪。

上下文结构定义在 \verb|src/interrupt/context.rs| 中，包括 \verb|Registers| 和 \verb|TrapContext| 两部分。\verb|Registers| 保存通用寄存器，\verb|TrapContext| 进一步保存 \verb|sstatus|、\verb|sepc|、\verb|scause|、\verb|stval| 和 \verb|kernel_sp|。这些结构使用 \verb|#[repr(C)]| 固定内存布局，并通过 \verb|offset_of!| 生成字段偏移常量，供汇编入口保存和恢复寄存器时使用。汇编代码由此不需要手写一组与 Rust 结构重复维护的偏移数字，减少了上下文结构调整时出现不一致的风险。

\section{异常与中断分发}

进入 Rust 层后，\verb|trap_handler| 通过 \verb|TrapContext::cause| 读取 \verb|scause|，并区分中断和异常。中断类主要处理 Supervisor Timer 和 Supervisor External，异常类主要处理 Breakpoint、Illegal Instruction、User Environment Call、Instruction/Load/Store Page Fault 以及若干访问异常。这里使用枚举和模式匹配表达分发逻辑，代码按照 \verb|Trap::Interrupt|、\verb|Trap::Exception|、\verb|Interrupt::SupervisorTimer|、\verb|Exception::UserEnvCall| 等分支展开，减少裸整数常量和多层判断。

  \centering
  \includegraphics[width=0.95\textwidth]{figures/trap-dispatch.pdf}
  \caption{中断与异常分发路径}\label{fig:trap-dispatch}
\end{figure}

对于时钟中断，系统使用 SBI timer 设置下一次时钟事件。当前实现将每秒中断次数设置为 60 次，定时器中断到来后更新用户态时间或内核态时间，增加当前进程的 CPU 使用计数，并在一秒边界更新系统时间。进程通过 \verb|sleep| 等待某个时间点时，系统会在超时后唤醒睡眠队列。时钟中断还会重新计算进程优先级，并在从用户态返回前检查是否需要调度。当前系统把抢占检查放在用户态返回边界，由 \verb|schedule_on_user_return| 触发调度，这与 Unix 风格在陷入返回点进行调度的思路保持一致。

外部中断通过 PLIC 的 claim/complete 流程处理。当前主要启用 UART0 外部中断；当 PLIC 返回 UART 中断号后，内核从串口读取输入字节，并交给 TTY 层处理。TTY 层完成回显、行规程和控制字符处理，输入中断字符时还会向进程发送相应信号。处理完毕后，内核向 PLIC 写回 complete。原 IA-32 版本通过 8259A 和键盘中断入口处理输入；RISC-V/QEMU virt 版本的输入路径改为 UART、PLIC 和 TTY 的组合。

异常处理依据异常来源区分用户态和内核态。用户态非法指令转换为 \verb|SIGILL|，用户态页面异常通常转换为 \verb|SIGSEGV|，访存对齐或总线类错误转换为 \verb|SIGBUS|。异常发生在内核态时，系统输出包含 \verb|scause|、\verb|sepc|、\verb|stval| 等信息的 panic 日志并停止。这一处理延续了 Unix V6++ 将用户态异常映射为信号的思路，同时利用 RISC-V 的 \verb|stval| 和 \verb|sepc| 信息提供调试线索。

\section{系统调用接口}

系统调用是用户程序请求内核服务的主要接口。当前用户态 C 库在 \verb|lib/src/syscall.h| 中封装了 \verb|__syscall0| 到 \verb|__syscall3| 等内联函数。系统调用号放入 \verb|a7|，参数依次放入 \verb|a0|、\verb|a1|、\verb|a2| 等寄存器，随后执行 \verb|ecall| 指令。处理完成后，返回值由内核写回 \verb|a0|。在用户库层，负返回值会通过 \verb|__syscall_ret| 转换为用户程序习惯的失败返回。

内核收到 \verb|ecall| 后，在 \verb|trap_handler| 中识别 \verb|Exception::UserEnvCall|，再调用 \verb|system_call::handle_user_ecall|。该函数先检查当前进程是否有待处理信号，再将 \verb|sepc| 前进 4 字节，避免 Trap 返回后重复执行同一条 \verb|ecall|；随后从 \verb|TrapContext| 中取出系统调用参数，写入 Unix V6++ 风格的 \verb|Userspace::args|，并把 \verb|a0| 位置作为返回值写入位置。内核按照系统调用号分发到进程管理、文件系统、时间、信号等处理函数。

  \includegraphics[width=0.95\textwidth]{figures/syscall-path.pdf}

\figref{fig:syscall-path} 展示了系统调用从用户态 C 库到内核处理函数再返回用户态的路径。当前系统保留了 Unix V6++ 的系统调用编号和主要语义，例如 \verb|exit|、\verb|fork|、\verb|read|、\verb|write|、\verb|open|、\verb|wait|、\verb|exec|、\verb|chdir|、\verb|sleep|、\verb|kill|、\verb|pipe| 和 \verb|signal| 等。这些调用支撑 Shell、TTY、管道和重定向路径，也是功能测试的主要对象。部分与当前平台关系不大的调用以空实现或 \verb|ENOSYS| 返回，例如若干未实现编号、\verb|trace| 和部分终端控制调用。

系统调用分发方式也随体系结构变化而调整。原版本通过 \verb|SystemCallTableEntry| 表保存参数个数和函数指针，系统调用号来自 \verb|eax|，参数从 \verb|ebx| 等寄存器复制到 \verb|u.u_arg|。RISC-V 版本使用 \verb|a7| 作为系统调用号，\verb|a0| 到 \verb|a5| 作为最多六个参数，并在 Rust 中通过 \verb|match| 表达分发逻辑。表驱动和模式匹配都能完成系统调用派发；当前版本采用 \verb|match|，便于同 Rust 的枚举、错误返回和模块函数调用结合，也便于在编译期检查分支书写是否符合类型约束。

系统调用处理中的错误返回沿用了 Unix 风格。内核内部以 \verb|PosixError| 表示错误原因，返回用户态时将错误码取负后写入 \verb|a0|。文件描述符无效、权限不足、找不到文件、系统调用未实现等情况，都通过统一的错误枚举返回。对于沿用原 Unix V6++ 文件系统处理习惯的函数，当前代码提供 \verb|trap_ret| 和 \verb|trap_void| 包装函数，将 \verb|Userspace::error| 转换为 Rust 的 \verb|KResult|。该处理保留已有 Unix V6 风格流程，也使新写的 Rust 代码可以使用 \verb|Result| 表达成功或失败。
