\chapter{系统总体设计}\label{chap:system-design}

本章说明 Unix V6++ RISC-V/Rust 重构版本的总体设计。这里的重构不是把 C++ 源文件逐句改写成 Rust，而是以保留 Unix V6++ 教学语义为基础，重新适配 RISC-V 平台的启动方式、特权级机制、地址空间组织、设备模型和用户程序 ABI。后续章节会分别展开启动、Trap、进程、设备交互和构建验证，本章先给出这些内容之间的结构关系。

\section{原 Unix V6++ 系统分析}

重构前的 Unix V6++ 面向 IA-32 平台，内核主体采用 C++ 语言实现。其整体结构延续 Unix V6 的设计思想，以进程、文件、inode、缓冲区、设备和系统调用为核心抽象，同时通过 C++ 类对各个模块进行封装。该版本能够在传统 PC 仿真环境中运行，并通过引导扇区、保护模式初始化、中断描述符表、页表、ATA 磁盘驱动和终端设备等机制完成一个小型 Unix-like 系统所需的基本功能。

教学使用中，原系统的优点在于模块完整、层次直观，能够体现操作系统内部各部分的协作关系。例如，用户程序通过系统调用进入内核，系统调用再调用文件系统或进程管理模块；文件系统通过 inode 和缓冲区管理访问块设备；进程调度依赖时钟中断和进程状态转换。这些机制共同构成了一个可观察、可修改、可调试的教学内核。

移植时，原系统也暴露出较强的平台耦合。启动代码依赖 IA-32 实模式到保护模式的切换；中断处理依赖 GDT、IDT、8259A 等 PC 平台机制；块设备访问依赖 ATA/IDE 设备模型；用户程序格式和运行约定也与原平台紧密相关。若希望将 Unix V6++ 迁移到 RISC-V 教学平台，仅保留上层接口是不够的，必须重新设计体系结构相关层，并调整内核模块之间的边界。

\section{重构后系统总体架构}

重构后的系统以 RISC-V 64 位平台为目标，运行环境选用 QEMU virt 机器和 OpenSBI。内核主体采用 Rust 语言实现，用户态库、Shell 和常用用户程序仍使用 C 语言编写，并通过 RISC-V 交叉工具链编译为 ELF64/RISC-V 可执行文件。系统运行时由 QEMU 加载内核，内核完成初始化后创建初始进程，加载用户态 Shell，最终形成可交互的教学操作系统环境。

重构后系统可以分为六个部分：启动与平台层、地址空间和页资源层、Trap 与系统调用层、进程管理层、文件设备与终端层、用户态支持层。启动与平台层负责 OpenSBI 入口、串口输出、平台常量和特权寄存器访问；地址空间和页资源层负责 Sv39 页表、内核栈和用户空间维护；Trap 与系统调用层负责上下文保存、时钟中断、外部中断和系统调用分发；进程管理层负责进程控制块、调度、上下文切换、fork/exec/wait/exit 和信号处理；文件设备与终端层向上提供 Unix V6 文件接口、VirtIO 块设备和 TTY；用户态支持层则把 C 用户库、Shell 和测试程序编译为 ELF64/RISC-V 程序，并通过系统调用与内核交互。

当前代码结构也体现了上述划分。内核入口和初始化流程位于 \verb|src/lib.rs|；RISC-V 页表和特权寄存器相关代码位于 \verb|src/machine/|；物理页、内核栈和交换区管理位于 \verb|src/mm/|；Trap、时钟、PLIC 和系统调用分发位于 \verb|src/interrupt/|；进程管理位于 \verb|src/proc/|；文件系统位于 \verb|src/fs/|；块设备、缓冲区和 VirtIO 驱动位于 \verb|src/dev/|；终端处理位于 \verb|src/tty.rs|。这些目录不是简单按文件类型归类，而是大致对应一次 Shell 命令运行时经过的路径：用户程序发起系统调用，内核进入 Trap，进程管理决定执行流，文件或设备层完成具体访问，结果再返回用户态。

\section{移植与重构方案}

本课题采用“平台相关层先行、核心语义逐步迁移、用户态闭环验证”的方案。先实现最小可启动内核，使系统能够在 QEMU virt 平台下进入 Rust 入口并输出调试信息；随后建立 Sv39 页表和页级资源管理，使内核能够访问自身数据结构、设备 MMIO 区域和用户空间；再实现 Trap 框架、时钟中断和系统调用入口，为进程调度和用户程序运行提供基础；最后接入文件接口、块设备、TTY 和 Shell。到这一步，验证对象不再只是内核日志，而是用户能在串口终端中执行命令的系统。

语言重构并不意味着 Rust 内核可以回避裸机系统必须面对的底层操作。页表修改、物理地址转换、MMIO 访问、Trap 上下文保存和进程上下文切换仍然需要裸指针、内联汇编或受控的 \verb|unsafe| 代码。重构的重点是把这些操作限制到相对集中的模块内，上层代码则用结构体、枚举、trait 和模块边界表达资源所有权与状态转换。例如，文件引用和 inode 引用通过封装类型管理，进程状态用枚举表达，设备访问通过块设备和字符设备接口提供统一入口。

体系结构迁移需要处理 RISC-V 与 IA-32 在启动方式、中断模型和地址空间组织中的差异。重构后系统不再使用 IA-32 的 GDT、IDT、TSS 和 8259A，而是使用 RISC-V 特权架构提供的 \texttt{stvec}、\texttt{sscratch}、\texttt{sepc}、\texttt{scause}、\texttt{sstatus} 和 \texttt{satp} 等寄存器完成异常中断处理和地址空间切换\cite{riscv_privileged_20211203}。设备访问不再依赖传统 PC 的 ATA/IDE 模型，系统改为面向 QEMU virt 平台，通过 MMIO 访问 UART、PLIC 和 VirtIO Block 设备\cite{qemu_riscv_doc}。

用户态适配保留 C 语言用户库和 Shell，使用户态编程接口尽量接近原 Unix V6++ 的使用习惯。用户程序通过 RISC-V 交叉编译工具链生成 ELF64 可执行文件，内核处理 \texttt{exec} 系统调用时解析 ELF 程序头，将代码段、数据段和用户栈装入用户地址空间，并按照约定传递 \texttt{argc} 和 \texttt{argv}。用户库封装 \texttt{ecall} 指令，提供 \texttt{fork}、\texttt{execv}、\texttt{read}、\texttt{write}、\texttt{open}、\texttt{pipe}、\texttt{signal} 等接口，Shell 和常用用户程序由此获得新平台运行入口。

\section{关键设计取舍}

本课题的首要目标是完成教学操作系统面向 RISC-V 平台的可运行迁移，设计取舍以“保留核心语义、控制实现复杂度、便于后续教学扩展”为原则。对于 Unix V6++ 已有的进程、文件、inode、缓冲区和 Shell 交互等教学核心内容，重构后系统尽量保留其概念模型和调用关系；对于与 IA-32 平台强绑定的启动、中断和设备代码，则按照 RISC-V/QEMU virt 平台重新实现。

内核模块划分没有把所有功能包装成过度通用的框架，而是保持教学内核所需的直接性。进程管理模块维护进程表、调度状态和上下文切换；文件接口围绕 inode、打开文件表和缓冲区展开；设备模块通过块设备和字符设备抽象支撑文件系统和 TTY。这样的边界方便论文和实验追踪一次系统调用：它从用户态进入 Trap，经过进程和文件对象，可能等待设备 I/O，最后回到 Shell。

运行平台选择 QEMU virt 作为主要验证环境。该平台能够稳定提供 RISC-V 处理器、OpenSBI、UART、PLIC 和 VirtIO 设备，避免了真实硬件差异对本科毕业设计验证过程的干扰。同时，Makefile 中提供了 \verb|qemu-riscv64| 和 \verb|qemu-riscv64g| 目标，分别用于普通运行和 GDB 调试，便于观察启动日志、Trap 上下文、进程切换和文件系统访问过程。

功能边界聚焦于单机教学内核的基本闭环：内核能够启动，能够建立地址空间和异常中断处理，能够运行用户态程序，能够通过系统调用访问文件和创建进程，能够通过终端与 Shell 交互。更复杂的性能优化和内核功能扩展只作为后续可研究方向，不写入已完成工作范围。这样可以让论文主体集中到跨体系结构移植、Rust 重构和可运行验证本身。

重构后系统形成了以 RISC-V 平台机制为底层基础、以 Rust 内核模块为主体、以 Unix V6++ 教学语义为上层目标的结构。后续章节将分别围绕启动与内存管理、中断与系统调用、进程管理、文件系统与设备、构建测试等内容展开说明。
