\chapter{重构与架构改进}\label{chap:refactor-highlights}

第 2、3 章分别讨论了 RISC-V
平台机制和进程用户态路径，本章从重构对比的角度说明系统架构的变化，讨论平台迁移和语言重构带来的具体工程差异。重构前的
\verb|main| 分支已经提供了可用于教学的 Unix V6++
内核；当前版本要解决的问题，是让这套教学语义在 RISC-V/QEMU virt 平台、Rust
内核和 ELF64/RISC-V 用户态环境中重新连通，并引入 Rust
的一系列新特性，带来架构上的改进和优化。

\section{跨体系结构迁移}

Unix V6++ 从 IA-32 迁移到 RISC-V 时，最先改变的是内核与硬件之间的契约。原系统的启动路径依赖引导扇区、实模式到保护模式切换、GDT、IDT、TSS、8259A 和 ATA/IDE 等传统 PC 机制；当前系统则经由 QEMU virt 与 OpenSBI 进入内核，使用 \verb|stvec|、\verb|sscratch|、\verb|scause|、\verb|sepc|、\verb|sstatus|、\verb|satp|、PLIC、UART 和 VirtIO Block 组织运行环境。两者之间没有直接的一一替换关系，启动代码、链接脚本、页表布局、中断入口、外设访问和用户态返回路径都需要重新建立。

从源码变化看，改动涉及内核主体、用户库、构建脚本和镜像工具。原
\verb|src/kernel/|、\verb|src/machine/|、\verb|src/interrupt/|、\verb|src/proc/|、\verb|src/dev/|、\verb|src/fs/|
等 C++ 模块被 Rust 模块重新表达；用户态 C 库新增 RISC-V 系统调用封装和启动入口；顶层 Makefile 需要同时组织 Cargo、RISC-V 交叉 GCC、链接脚本、文件系统镜像生成和 QEMU 运行目标。这里并不是逐个函数的翻译，而是多个边界同时移动：体系结构边界、语言边界、设备边界、用户程序 ABI 边界和构建边界需要同时闭合。

\section{RISC-V 重构的亮点}

在我们的 RISC-V 重构中，首先我们把原先分散在 IA-32 平台机制中的入口路径收束到了 RISC-V 特权架构的统一 Trap 模型。原系统中系统调用、时钟中断、键盘中断和异常分别依赖 IDT 表项和不同入口代码；当前系统通过 \verb|_trap_entry| 保存统一的 \verb|TrapContext|，再在 Rust 层根据 \verb|scause| 分发中断、异常和系统调用。这样做并不是减少了底层复杂性，而是让事件入口和上下文结构更集中，学生可以沿同一个结构观察用户态进入内核、内核处理事件、再通过 \verb|sret| 返回用户态的完整过程。

其次，我们进行了用户态 ABI 的整体替换。原用户程序格式和 x86 调用约定不能直接用于 RISC-V。当前系统重建了 C 用户库中的 \verb|ecall| 封装，使用 \verb|a7| 传递系统调用号，使用 \verb|a0| 到 \verb|a5| 传递参数和返回值；内核在 \verb|exec| 中解析 ELF64/RISC-V 程序头，装入 \verb|PT_LOAD| 段，构造 \verb|argc/argv| 用户栈，并设置 \verb|sepc|、用户栈指针和参数寄存器。由此，用户态 Shell 和常用命令不只是被重新编译，而是获得了与 RISC-V 内核 Trap 返回路径一致的运行入口。

除此以外，设备模型的迁移也没有破坏 Unix 风格文件接口。原系统面向 ATA/IDE、键盘和显示输出路径，当前系统面向 UART、PLIC 和 VirtIO Block。设备层变化较大，但上层仍通过字符设备、块设备、缓冲区、inode 和文件描述符访问资源。Shell 读取终端、普通程序读写文件、管道和重定向仍使用统一的系统调用接口。这样的处理使硬件平台变化能够在教学中被清楚观察，同时不会要求用户态程序直接感知 VirtIO 或 PLIC 的细节。

\section{Rust 重构带来的特性及其意义}

Rust 重构的意义主要体现在资源边界表达上。内核仍然必须保留 \verb|unsafe|：页表项修改、MMIO 访问、裸指针读写、Trap 入口和上下文切换都无法完全交给安全抽象。但当前实现把这些操作限制在较集中的模块内，并用 Rust 类型表达上层对象之间的所有权关系。页资源被封装为 \verb|KernelPages|、\verb|UserPages|，进程内核栈由 \verb|KernelStack| 持有，文件和 inode 引用由 \verb|FileRef|、\verb|InodeRef| 管理，中断开关由 \verb|IrqGuard| 在作用域结束时恢复。

  \centering
  \includegraphics[width=0.95\textwidth]{figures/mm-lifetime.pdf}
  \caption{页资源生命周期管理方式对比}\label{fig:mm-lifetime}
\end{figure}

\figref{fig:mm-lifetime} 展示了资源生命周期表达方式的变化。原版本中，内存块、inode 和文件对象通常以地址、指针或表项编号的形式在调用链中流转，释放动作由具体路径显式调用；当前版本把页资源、内核栈、文件引用、inode 引用和中断保护封装为带生命周期的对象，并在 \texttt{Drop} 或 guard 离开作用域时完成回收或状态恢复。C++ 同样支持 RAII，原 Unix V6++ 的实现更多服务于还原早期 Unix 的表结构和显式管理方式；本文的 Rust 重构是在平台迁移过程中重新表达资源边界，使读者在追踪进程退出、文件关闭和页回收时更容易看到资源由谁持有、何时释放。

进程管理也能体现 Rust 重构的优势。原 \verb|main| 分支用固定进程数组表示进程槽位，当前系统使用 \verb|Vec<Box<Process>>| 保存进程对象；父进程 \verb|wait| 到僵尸子进程后移除对应 \verb|Box|，内部的内核栈、文本段引用、用户页等字段随对象生命周期回收。进程状态用枚举表达，信号号也从裸整数转换为 \verb|Signal| 枚举并通过转换接口校验。这样的写法仍保留 Unix V6++ 的进程状态名称和教学语义，但将一部分状态合法性和资源归属写入类型结构中。

错误处理路径也发生了变化。原系统中不少函数通过全局 \verb|User| 结构中的错误字段传递失败原因；当前系统在新写的 Rust 路径中更多使用 \verb|Result|、\verb|KResult| 和 \verb|PosixError| 表示错误，再在系统调用返回时转换为用户态负错误码。这样既保留 Unix 风格 ABI，又使内核内部函数可以把成功值和失败原因放在类型签名中表达。对于教学内核而言，这种表达有助于区分正常控制流、错误返回和必须停止内核的 panic 路径。

\section{保留教学语义的取舍}

本次重构没有把 Unix V6++ 改写成另一个完全不同的教学系统。进程状态名称、\verb|sleep|/\verb|wakeup|、\verb|fork|/\verb|exec|/\verb|wait|、inode、文件描述符、TTY、Shell 和常用命令仍然保留，学生仍可以从 Shell 命令和系统调用现象进入内核。变化主要发生在这些语义的底层承载方式上：x86 Trap 栈帧换成 RISC-V \verb|TrapContext|，PE/原平台程序换成 ELF64/RISC-V 程序，ATA/IDE 换成 VirtIO Block，显式资源释放路径更多转为 Rust 类型的生命周期边界。这种处理避免了系统与原先设计偏差过大，造成语义差异，并因此导致学生理解的困难，以及教学上的不便。相比于把全部模块铺开讨论，本文更适合围绕几个迁移难点展开：第一，RISC-V 特权架构下的启动、Trap 和系统调用路径；第二，进程生命周期与 ELF 用户程序加载；第三，Rust 类型系统如何服务于内核资源边界。它们共同构成当前系统区别于原设计的主要变化。

\section{当前实现的边界}

当前系统仍是教学内核，不追求通用操作系统的完整功能。部分系统调用仍为空实现或返回 \verb|ENOSYS|，\verb|wait| 对子进程退出状态和时间统计的处理较简化，信号机制尚未覆盖完整的屏蔽、排队和默认动作细节。测试也以构建检查、启动日志观察和 QEMU 交互测试为主，自动化回归还需要继续补充。这些边界并不削弱本文的主线，反而说明当前系统的重心集中在跨体系结构迁移、Rust 重构和可运行教学闭环上；后续扩展可以在这一框架上继续补齐更细的 Unix 语义和测试体系。
